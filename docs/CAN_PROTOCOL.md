# F103 与 H743 的 CAN 控制协议 v2

两端为 STM32F103C8T6 与 STM32H743IIT6。当前没有转速传感器或编码器，
控制量为 **PWM 占空比**，不发送目标转速或实际转速，也不做闭环转速控制。
协议版本为 2，与之前的监测协议不兼容，必须同时更新两端固件。

两端源码分别在 `260920_completef103/user` 与 `260920_completeh743/User` 中维护。
各工程独立构建，并使用各自的 `can_protocol.h`；修改协议时需同步更新两端定义。

## 总线和连接

- 经典 CAN，500 kbit/s，11 位标准数据帧，DLC 固定 8，禁用 CAN FD 和 BRS。
- F103：PA12/CAN_TX、PA11/CAN_RX；CAN 时钟 36 MHz，Prescaler=8、BS1=5 TQ、BS2=3 TQ、SJW=1。
- H743：PB9/FDCAN1_TX、PB8/FDCAN1_RX；FDCAN 内核时钟 36 MHz，NominalPrescaler=8、TimeSeg1=5、TimeSeg2=3、SJW=1。
- 两块 MCU 各经 CAN 收发器连接，CANH 接 CANH、CANL 接 CANL，连接信号参考地。
  总线两个末端各放置 120 Ω 终端电阻，检查板载终端以免重复并联。
  MCU 的 TX/RX 不能当成 CANH/CANL 直接相连。

## 报文总览

| ID | 方向 | 周期 | 内容 |
|---|---|---|---|
| `0x100` | H743 → F103 | 500 ms | 管理节点心跳 |
| `0x201` | H743 → F103 | 50 ms | 使能、目标 PWM 占空比、过流停机阈值、命令序号 |
| `0x301` | F103 → H743 | 50 ms | 电流、温度、实际 PWM 输出占空比、保护与通信状态 |
| `0x302` | F103 → H743 | 500 ms | 电机节点心跳 |
| `0x3F1` | F103 → H743 | 故障触发 | 首次锁定的故障、故障时电流峰值和温度 |

所有多字节整数均为小端，不直接发送 C 结构体或浮点数。
心跳表示节点的通信任务仍在周期运行；不代表传感器正常或电机实际旋转。
周期和超时是软件设定值，受 10 ms RTOS tick 和任务调度影响。

## `0x201`：电机控制命令

| 字节 | 内容 |
|---|---|
| 0 | 版本，固定 `0x02` |
| 1 | 命令序号，0～255 循环；即使命令参数不变，也必须继续递增 |
| 2 | 使能：0 停止驱动，1 请求使能；其他值无效 |
| 3 | 目标 PWM 占空比，整数 0～100% |
| 4～5 | 过流停机阈值，`uint16_t`，单位 mA，有效范围 1～160 |
| 6～7 | 保留，必须为 0 |

默认参数为 **使能 1、占空比 50%、过流停机阈值 160 mA**。
使能为 0 时输出归零；使能为 1 且占空比为 0 时也不驱动。
电流字段是“达到阈值后锁定停机”，不是恒流调节。F103 本地硬上限仍为 160 mA；
非法范围整帧拒收，不静默截断或替换。降低阈值时，也立即检查最近采到的峰值。

F103 只在 H743 心跳有效且报文接收年龄小于 200 ms 时接受新命令。
首条命令允许任意序号；后续使用模 256 差值 1～127 判断为新命令，支持 255→0。
重复或倒序命令不能更新参数或续期。例外：格式正确且未过期的禁用命令始终可以停机，
但只有通过心跳与新序号检查后才更新接受序号和看门时间。
H743 重启导致序号重新计数时，可能触发拒收及通信停机；恢复流程是修复通信后手动复位 F103。

## `0x301`：测量与状态

| 字节 | 内容 |
|---|---|
| 0 | 版本，固定 `0x02` |
| 1 | 最近接受的命令序号；只有 `COMMAND_SEEN=1` 时才有意义 |
| 2～3 | 中位数电流，`uint16_t`，单位 0.1 mA；`0xFFFF` 无效 |
| 4～5 | 温度，`int16_t`，单位 0.1 ℃；`0x8000` 无效 |
| 6 | 当前 PWM 输出占空比，0～100%；停止或锁定时为 0 |
| 7 bit 0～2 | 保护状态，见下表 |
| 7 bit 3 | `ENABLED`：目前保留的使能请求；不代表保护允许输出 |
| 7 bit 4 | `COMMAND_SEEN`：本次启动已接受过有效命令 |
| 7 bit 5 | `HOST_ONLINE`：H743 心跳未超时 |
| 7 bit 6 | `COMMAND_FRESH`：有效新命令未超时 |
| 7 bit 7 | 保留，必须为 0 |

| 值 | 状态 | 含义 |
|---|---|---|
| 0 | `WAIT_SENSORS` | 等待满足启动条件的温度和电流 |
| 1 | `READY` | 本地保护允许输出，仍需使能及非零占空比 |
| 2 | `OVERHEAT_LATCHED` | 过温停机锁定 |
| 3 | `SENSOR_FAULT_LATCHED` | 传感器或 ADC 异常锁定 |
| 4 | `OVERCURRENT_LATCHED` | 过流停机锁定 |
| 5 | `COMM_FAULT_LATCHED` | 通信故障停机锁定 |

中位数电流不是 PWM 电流的平均值或有效值；本地过流检查使用一批 15 点的最大值。
PWM 字段是实际写出的占空比，不是实测转速。命令序号回显表示命令被接收处理，
不保证电机已转动；必须同时检查保护状态和 PWM 字段。
原有 INA180 输出电压和每批峰值仍在 F103 本地串口显示，不另占周期 CAN 帧。

## `0x100` 与 `0x302`：双向心跳

| 字节 | 内容 |
|---|---|
| 0 | 版本，固定 `0x02` |
| 1 | 心跳序号，0～255 循环 |
| 2 | H743 固定 0；F103 为保护状态 0～5 |
| 3 | H743 固定 0；F103 为诊断标志 |
| 4～7 | 发送节点 RTOS 运行秒数，`uint32_t`；tick 回绕后重新计数 |

F103 心跳字节 3：bit 0 表示发生过接收读取失败/队列溢出，bit 1 表示发生过发送提交失败，
bit 2 表示已接受过有效命令，bit 3 表示使能请求。bit 4～7 为 0。
接收丢弃和发送失败标志在本次启动内保留。发送失败计数不覆盖全部物理层错误；
HAL 返回成功只表示交给硬件，不代表对端收到。

## `0x3F1`：故障事件

| 字节 | 内容 |
|---|---|
| 0 | 版本，固定 `0x02` |
| 1 | 故障事件序号；当前每次 MCU 启动只锁定首个故障，因此固定为 0 |
| 2 | 故障代码，见下表 |
| 3 | 生成事件报文时最近接受的命令序号；未接受过命令时为 0 |
| 4～5 | 锁定瞬间保留的采样电流峰值，0.1 mA，`0xFFFF` 无效 |
| 6～7 | 锁定瞬间保留的温度，0.1 ℃，`0x8000` 无效 |

| 代码 | 含义 | 当前支持情况 |
|---|---|---|
| 1 | 过流 | 已实现 |
| 2 | 堵转 | 保留；当前硬件不能可靠区分堵转与其他过流 |
| 3 | 过温 | 已实现 |
| 4 | 编码器故障 | 保留；未安装编码器 |
| 5 | 通信故障 | 已实现 |
| 6 | 传感器/ADC 故障 | 已实现 |

首次故障保存测量快照，停机后测得的零电流不会覆盖它。
同一事件向硬件提交 3 次，各次间隔至少 50 ms；邮箱忙则保留待发事件并在后续周期重试。
这不是应用层确认机制，总线断开时不能保证事件送达；故障状态持续包含在 `0x301`、`0x302` 中。
H743 保存最近故障供程序读取，重发仅覆盖同一事件；`faultAvailable` 表示保存过历史事件，
不表示本次重启后的实时故障，当前故障以状态帧为准。

## 启动、失联与恢复

1. H743 上电默认使能，每 50 ms 周期发送命令，每 500 ms 发送心跳。
2. F103 初始化保持 PWM 为 0。收到有效心跳、有效命令，且同批温度有效并低于 50℃、
   电流有效且低于阈值后，才按请求占空比输出。正常默认是 50%。
3. 启动后 1.5 秒仍未接受有效命令，锁定通信故障。已接受命令后，连续 200 ms
   没有有效新命令即锁定停机；即使心跳仍来，也不能代替控制命令。
   已收到心跳后，连续 1.5 秒没有有效心跳也锁定停机；即使命令仍来，也不能代替心跳。
4. 故障后 AIN1、AIN2 均为 0，电机滑行停止。只保留首次故障原因。
   通信恢复、重新使能、温度或电流下降都不能解除锁定，需手动复位 F103。
5. H743 用两个接收时间分别判断：状态数据小于 250 ms 才为新鲜，电机心跳小于 1.5 秒才在线，
   两者同时满足才显示 `ONLINE`。离线保留最后数据并显示年龄，不清零伪装为新数据。

双方接收中断只做校验、复制和入队，静态队列 16 帧，保留中断接收时间。
通信任务每轮最多处理 16 帧，再延时 10 ms；本地采样保护任务优先级更高，串口另用低优先级任务。
F103 在处理本轮队列之前检查超时，旧的排队报文或迟到的新命令不能取消已发生的通信故障。
双方发送不阻塞采样，周期发送忙则下个周期发送最新值。
当前未启用硬件自动重发，也未新增 bus-off 自动恢复；总线恢复后如仍不能通信，需复位节点。

## H743 程序接口

接口位于 `User/drv_can.h`；默认参数也在该头文件。
调用接口只更新期望命令，下一个 50 ms 发送周期生效；返回 `HAL_OK` 不等于对端已执行。
可以在 `FDCAN_Init()` 后或后续按键/上位机任务中调用：

```c
Can_SetMotorCommand(1, 50, 160); // 使能，50% 占空比，160 mA 停机阈值（默认）
Can_SetMotorCommand(1, 60, 140); // 调为 60%，140 mA 停机阈值
Can_SetMotorCommand(0, 0, 160);  // 正常停机，不清除故障

CanRemoteSnapshot snapshot;
Can_GetRemoteSnapshot(&snapshot); // 温度、电流、PWM、状态、心跳、最近故障及数据年龄
```

`Can_GetMotorCommand()` 读取期望参数；其中 sequence 不作为已发送序号，实际回显见 `snapshot.telemetry.commandSequence`。
F103 的 `Motor_SetForwardDuty()` 保留供实验使用，但不能绕过远程使能门控或故障锁定；
当前联动模式的启停调参应统一从 H743 接口进入。

## 报文示例

序号 7，使能 50%，160 mA 阈值；实际温度 25.0℃、电流 30.0 mA、输出 50%、状态 READY，
心跳和命令均有效：

```text
0x201  DLC=8  02 07 01 32 A0 00 00 00
0x301  DLC=8  02 07 2C 01 FA 00 32 79
```

## 验证

主机测试运行 `python tests/communication/run_tests.py` 和 `python tests/thermal/run_tests.py`。
通信测试直接读取相邻的 `260920_completeh743` 实际工程；可用 `--h743-project 路径`
指定位置，或用 `--target f103` 仅测试 F103，不要求本地存在 H743 工程。
测试涵盖默认使能、50 ms 命令周期、启停、调参边界、序号回绕和重复、非法帧、旧队列数据、
两类通信超时、故障保持、事件快照和重试、计时回绕、温度与电流保护。

板上联调时需要同时烧录两端新固件，并核对五个 CAN ID。正常启动应看到 50% PWM；
测试禁用后 PWM 归零；分别停止命令和心跳验证停机及状态码 5；恢复通信后必须仍停机。
最后在可控条件下验证过流、过温的状态、事件和手动复位流程。
目前完成软件测试与固件编译，尚未烧录或实测双板总线。

硬件仍为 INA180A1、1 Ω，160 mA 是已确认的实验阈值，启动可能触发过流。
没有传感器就不能确认真实转速、堵转或是否机械停止。软件保护依赖 MCU/调度器执行，
本次未增加独立硬件关断或看门狗，不能覆盖 CPU 停止执行的情况。
